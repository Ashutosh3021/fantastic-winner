# Pyronites setup and wireup

Goal: take the user from "nothing" (or "half set up") to a working client call against a running backend, with secrets handled safely.

## Hard rules (read before anything else)

1. **Never clone, read, or `pip install -e` the Pyronites repository.** Do not read `docs/syntax.md`, do not browse GitHub for the source, do not look for a local checkout. This skill is complete on its own. If some checkout happens to be on disk, ignore it — reading it is a bug, not diligence.
2. **Install the client from PyPI only:** `pip install pyronites`. That is the entire dependency story for app code.
3. **Verify the API against the installed package,** not against any repo:
   ```bash
   python -c "import pyronites, inspect, os; print(os.path.dirname(inspect.getsourcefile(pyronites)))"
   ```
   If a call looks unfamiliar, read the file that command prints. That is the only source of truth.
4. **Never invent credentials.** No URLs, no emails, no passwords, no keys, no project ids. Ask.
5. **Never echo, log, or commit a password or raw API key.**

## 0. Collect inputs first — ask, then proceed

Do not start provisioning until you have the four values below. Ask for the ones you are missing **in a single message**, as a short list. Never guess any of them.

| Input | Why it is required | If missing |
|---|---|---|
| `PYRONITES_URL` | base URL of the user's own backend | Ask. Default `http://localhost:8000` **only** after the user confirms local dev. |
| `email` | needed to create the key or tables | Ask. Never invent. |
| `password` | needed to create the key or tables | Ask, via env var `PYRONITES_PASSWORD` or a `getpass` prompt — never pasted into a shell command. |
| **`project_id`** | every project-scoped route is keyed by it | **Ask.** Get it from `GET /auth/me` → `last_project_id`, or `GET /projects`. Never invent or reuse a default-looking value. |
| **API key with `admin` scope** | creating keys and tables requires `admin` | **Ask** whether they have one. If not, mint one (step 4). |

**Gate:** before creating tables or keys, state back to the user the exact `project_id` and key scopes you are about to use, and get a yes. A wrong `project_id` silently targets the wrong database.

If the user gives you a key that lacks `admin`, do not silently escalate — tell them it cannot create tables and ask whether to mint an `admin` key.

## 1. Confirm the backend is reachable

```bash
curl -s -w "\n%{http_code}\n" "$PYRONITES_URL/health"   # expect 200 and {"status":"ok"}
```

If it is not running, ask the user how they run it. Offer these, in order:

```bash
docker compose up --build        # if they have the repo checked out
python -m uvicorn backend.app:app --host 0.0.0.0 --port 8000   # if running from a checkout
```

**Do not clone the repository yourself** — the user owns their deployment. If they have not deployed anything yet, ask whether they want to; do not assume.

If `/health` works but later endpoints 404, the path layout may differ by version. Check `$PYRONITES_URL/openapi.json` (or `/docs`) and trust it over this document.

## 2. Authenticate

Signup first, then fall back to login on 409 (already exists). Use one `requests.Session` so the `session_token` cookie carries through steps 3–5.

```python
import os, getpass, requests

url = os.environ.get("PYRONITES_URL", "http://localhost:8000")
email = os.environ["PYRONITES_EMAIL"]
password = os.environ.get("PYRONITES_PASSWORD") or getpass.getpass("Pyronites password: ")

s = requests.Session()
r = s.post(f"{url}/auth/signup", json={"email": email, "password": password})
if r.status_code == 409:
    r = s.post(f"{url}/auth/login", json={"email": email, "password": password})
r.raise_for_status()
```

Password must be ≥ 8 characters. Auth endpoints are limited to roughly 20 requests/min per IP, so don't retry in a tight loop (see error table).

## 3. Resolve `project_id`

```python
me = s.get(f"{url}/auth/me").json()
project_id = me.get("last_project_id")
```

If `last_project_id` is null, list projects and let the user pick:

```python
projects = s.get(f"{url}/api/projects").json()
```

Show the user the names and ids and ask which one. **Do not guess.** Then pin it for every later step:

```python
import os
os.environ["PYRONITES_PROJECT_ID"] = project_id   # tell the user this value
```

Prefer project-scoped paths `/api/projects/{project_id}/...`. Fall back to the unscoped paths only if the scoped ones 404.

## 4. Create the admin API key

Needs a session (already have one from step 2) or an existing admin key. Default to least privilege: `read` + `write` for app code; `admin` only when the key itself must create tables or keys.

```python
r = s.post(f"{url}/api/projects/{project_id}/api/keys", json={
    "name": "app-key",
    "scopes": ["read", "write", "admin"],
})
r.raise_for_status()
key = r.json()["key"]           # shown ONCE, e.g. pyro_live_...
```

If the scoped route 404s, use the unscoped `POST /api/keys` with `project_id` in the body.

Handle the key immediately:

1. Write it to `.env` with owner-only permissions, never to chat or logs:
   ```python
   from pathlib import Path
   env = Path(".env")
   with open(env, "a") as f:
       f.write(f"PYRONITES_URL={url}\n")
       f.write(f"PYRONITES_KEY={key}\n")
       f.write(f"PYRONITES_PROJECT_ID={project_id}\n")
   env.chmod(0o600)
   ```
2. Make sure `.env` is in `.gitignore` (append if missing).
3. Tell the user the key was saved and where; do not print it back. If they lose it, create a new one — it cannot be retrieved.

## 5. Create tables

Needs `admin`. Do this only for tables the user actually asked for.

```python
r = s.post(f"{url}/api/projects/{project_id}/tables", json={
    "table": "notes",
    "columns": [
        {"name": "id", "type": "TEXT"},
        {"name": "title", "type": "TEXT"},
        {"name": "body", "type": "TEXT"},
        {"name": "created_at", "type": "DATETIME"},
    ],
    "primary_key": "id",
})
```

Rules:
- Column types: `TEXT INTEGER REAL BLOB NUMERIC BOOLEAN DATETIME DATE JSON`.
- Table names match `^[A-Za-z_][A-Za-z0-9_]*$` and must not be reserved: `users sessions api_keys migrations projects storage_files password_reset_tokens oauth_identities`.
- Run `GET .../tables` first. If the table exists, show the user the existing schema instead of recreating it.
- Confirm the target `project_id` with the user before this call.

## 6. Install and wire the client

```bash
pip install pyronites
```

```python
import os
from pyronites import create_client, ApiError, AuthError, NotFoundError

client = create_client(
    url=os.environ["PYRONITES_URL"],
    key=os.environ["PYRONITES_KEY"],
)
```

Load `.env` with `python-dotenv` (`load_dotenv()`) or the framework's own mechanism if the project doesn't already export these variables.

### Client API cheat sheet

This is the full surface. Verify anything surprising against the installed package (hard rule 3).

```python
# Tables — Supabase-style chainable queries
client.table("notes").insert({"title": "Hello", "body": "World"})   # returns inserted row
client.table("notes").select().limit(10)                             # iterable of dicts
client.table("notes").select().eq("id", 1).order("created_at", desc=True)
client.table("notes").update({"title": "Updated"}).eq("id", 1)
client.table("notes").delete().eq("id", 1)

# Auth
client.auth.sign_in("user@example.com", "password")
client.auth.sign_out()
client.auth.user()

# Storage
meta = client.storage.upload("photo.jpg")   # returns dict with "id"
data = client.storage.download(meta["id"])

# Offline / cache policy (optional)
client = create_client(
    local_tables=["settings"],
    cache_tables=["catalog"],
    local_db_path="./.pyronites_local.db",
)

# Errors
from pyronites import ApiError, AuthError, NotFoundError
```

Use `list(...)` when you need a materialized list; the query builder is lazy.

## 7. Verify (don't declare success without this)

Insert one row into a real table, select it back, then delete it — or use a harmless `select().limit(1)` if the user does not want test data written. An empty select that returns without error also counts as a pass on a new table.

Report a checklist, marking each line done / skipped / failed:

- [ ] `/health` returns ok
- [ ] Auth worked (signup or login)
- [ ] `project_id` confirmed with the user
- [ ] Admin key created and saved to `.env` (mode 600), `.env` git-ignored
- [ ] Requested tables exist in the confirmed project
- [ ] `pip install pyronites` succeeded
- [ ] Smoke test passed against the confirmed project

## Errors: what to do

| Symptom | Likely cause → action |
|---|---|
| Connection refused / timeout | Backend not running or wrong URL → step 1 |
| 409 on signup | Account exists → log in instead |
| 401 | Bad credentials, expired session, or bad key → re-login or recreate key |
| 403 | Key lacks the scope → create a key with the needed scope, or use the session |
| 404 `table_not_found` | Create the table or fix the name |
| 404 on a route | Path differs by version, or wrong `project_id` → check `/openapi.json` |
| 429 | Rate limited → wait for the `Retry-After` header, then retry once |

Always show the user `detail.code` and `detail.message` from the error body; they usually name the exact fix.

If data went somewhere unexpected, the cause is almost always the wrong `project_id`. Re-check it before debugging anything else.

## Security rules

- Never invent credentials, URLs, or project ids; never log, echo, or commit a password or raw key.
- Least privilege for keys that ship in apps: `read`/`write`. Keep `admin` keys out of deployed code.
- Secrets live in `.env` or a secrets manager, not in source.

## Quick reference

| Action | Project-scoped path | Unscoped fallback | Auth |
|---|---|---|---|
| Health | `GET /health` | — | none |
| Signup / Login | `POST /auth/signup`, `POST /auth/login` | — | none |
| Current user (→ `last_project_id`) | `GET /auth/me` | — | session |
| List projects | `GET /api/projects` | — | session |
| Create key | `POST /api/projects/{pid}/api/keys` | `POST /api/keys` | session or admin |
| List / create table | `GET`/`POST /api/projects/{pid}/tables` | `/tables` | read / admin |
| Rows | `GET`/`POST`/`PATCH`/`DELETE /api/projects/{pid}/tables/{name}` | `/tables/{name}` | read / write |
